> **For agentic workers:** The Planner chat owns this plan, scope decisions, and independent milestone evaluation. ## Disposition of the earlier recommendations

| Recommendation | Decision and priority |
| --- | --- |
| 1. Refresh evidence | **Implement, P0**, after configuration and label preflights. Adjust “missing labels” to auditing current returned evidence and snapshot compatibility. Separate historical trace diagnostics, fresh local retrieval, and current live results. A complete coverage audit does not establish semantic success. |
| 2. Measure graph contribution | **Implement, P1**, as a bounded ablation using the existing runner, adapters, and score contracts. Existing `VectorContextRetriever` traverses graphs; it is not a vector-only baseline. Compare legacy/optimized separately from isolating graph contribution. Defer LLM reranking and large factorial searches. |
| 3. Investigate failures | **Implement, P0/P1**, beginning with boundary reproductions and existing cases. Reject unconditional threshold lowering, guessed acronym expansion, forced web fallback, or adding a broad state subsystem without evidence. Treat Mentor/mode and ambiguous-topic causes as hypotheses. |
| 4. Public reproducibility | **Adjust, P0:** document and automate meaningful secret-free offline tests using existing synthetic data/factories. Add tiny fixtures only for demonstrated gaps. The existing live demo remains the application showcase; a richer standalone corpus/storage/example package is optional and not an M1 dependency. Defer private corpus release and infrastructure-free production UI work. |
| 5. Automate checks | **Implement, P0**, by running meaningful existing checks on PRs and clearly separating asset/service integrations. Defer blanket coverage targets, exhaustive provider matrices, and unrelated cleanup. |
| 6. Recruiter presentation | **Implement in two deliveries:** P0 prominent live demo, truthful defaults, working links, offline check commands, and explicitly historical existing evidence; P1 new findings after measurement. Preferred approach: evidence and reproducibility first, then focused fixes and one bounded comparison. A README-only refresh would leave results unauditable; a broad architecture/provider migration would expand scope without proving quality.
